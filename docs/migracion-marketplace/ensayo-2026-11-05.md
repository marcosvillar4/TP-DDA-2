# Resumen de ensayo y validación estructural

## Ensayo

Se respaldó el esquema de origen y se restauró en una copia nueva descartable.
Se verificaron las definiciones de tablas, claves foráneas, índices, objetos
programables existentes y huellas de todos los registros originales. Se aplicaron
las tres operaciones estructurales únicamente sobre la copia.

Las columnas nuevas conservaron NULL para los pedidos anteriores y refresh_tokens
quedó vacía. Las pruebas de unicidad sobre inventario y token_hash rechazaron
duplicados con error 1062. Los datos ficticios de esas pruebas no se persistieron.

## Aplicación y arranque local

Después de la aprobación expresa, las tres DDL se aplicaron individualmente a la
base local marketplace. Se preservaron los registros históricos y las otras
bases. Las huellas de las columnas originales coincidieron antes y después.

El control de igualdad estricta de índices detectó la retirada automática de un
índice individual de inventario_id. El diagnóstico confirmó que la clave foránea
seguía definida, sin referencias huérfanas, y cubierta por el nuevo índice único
compuesto. No se recreó el índice ni se ejecutó DDL adicional para igualar el ensayo.

Spring Boot inició contra marketplace con ddl-auto=validate, servicios externos
deshabilitados y conexiones JDBC de solo lectura verificadas en el servidor.
GET /usuarios/me sin autenticación devolvió 401. El proceso temporal se detuvo y
la comparación posterior no detectó cambios de estructura o datos.

## Límites

Esta evidencia acredita migración estructural, conservación y arranque de la
versión evaluada. No certifica todas las reglas de datos legacy, rendimiento bajo
carga ni nuevas operaciones funcionales de escritura. No se distribuyen las bases,
respaldos, credenciales ni logs de esas comprobaciones.

Para otra instalación se debe repetir el [procedimiento manual](README.md).
Los scripts no son idempotentes y ya fueron aplicados en la base local evaluada.
